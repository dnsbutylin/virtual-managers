# virtual-managers

Платформа автоматизации первого касания в B2B-продажах. Одна программа
решает, кому, когда и с какого ящика писать. Письма отправляют отдельные
серверы — ячейки: у каждой свои ящики компании, она берёт задание на короткий
срок, отправляет письмо и сообщает, что письмо ушло. Короткий срок нужен,
чтобы одно письмо не ушло дважды. К ящику привязан номер компании: если
письмо уже ушло, известно, с какого номера звонить на телефон этой записи.

## Быстрый старт

Из корня репозитория в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev]"
.\.venv\Scripts\python -m pytest
.\.venv\Scripts\python -m vm.planning.capacity
```

## Статус

Этап 0. Контракты, расчёт мощности и тесты на месте. Работающего сервиса ещё нет.

Почта первого месяца — новые ящики Gmail компании, по 100 писем в день.
На 350, 455 и 591,5 тысячи касаний это 117, 152 и 198 ящиков.
Номер и код SMS даёт вендор. Ящики инженер заводит сам, руками: 117 пар — это 2–5 рабочих дней.
Ящики, которые уже пишут, остаются в старой отправке.
Карточка ящика лежит в своей базе, пароль — на ячейке, которая с него отправляет.
Ответ с положительным интентом уходит в AMOCRM. Диалог продолжает отдел.

Домены подключаются только если отдельный тест выиграет у этих ящиков.
Голос остаётся на зарубежном оркестраторе, который компания уже использует.
Мессенджеры идут после почты, с того же номера, на отдельном компьютере.
